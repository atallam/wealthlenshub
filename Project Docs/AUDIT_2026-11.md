## Gaps found
1. No route-level authorization tests; crypto/auth/auditLogger untested -> addressed in Phase 1 (auth sweep, crypto, auth, redaction).
2. Heavy endpoints rely only on the global 200/15min limiter: `import/detect`, `import_v2`, `tradebook`, `budget/upload`, `concall/analyze-text`. -> addressed in Phase 2.
3. Uploads accept any file type (size cap only) on import, import_v2, tradebook, budget.
4. 16 routers read `req.body` without schema validation (`budget` 11, `holdings` 7).
5. 17 raw `error: e.message` responses (notifications.js, import_v2.js, ...) bypass the prod-safe `sendError`.
6. Update-by-id writes without `user_id` (service key bypasses RLS).
7. No delete-account / purge path.
8. CI did not build or audit -> addressed in Phase 1.
9. No startup config validation (missing `ANTHROPIC_KEY` surfaces on first AI call).
10. CSP report-only.
11. Clutter: overlapping import routes, legacy SQL, duplicate migration numbers, dead Gmail references.
12. Frontend: `App.jsx` ~1,000 lines, 646 kB main chunk. -> **Fixed** (Phase 6): `App.jsx` is ~300 lines; main chunk 283 kB with lazy-loaded tabs.
13. Advisories: `zod` 3 (low practical risk), Express 4 `body-parser`/`qs` DoS. -> `zod` is the one remaining `npm audit` finding; validation is capped at 5,000 rows as a mitigation and the zod 4 upgrade is in `BACKLOG.md`.

## Found and fixed while writing Phase 1 tests
- Audit-log redaction matched exact key names only, so `userSecret`, `user_secret`, `public_token`, `pdfPassword`, `apiKey` etc. would have been stored in `audit_logs`. Now pattern-based (`lib/auditLogger.js`), covered by `tests/auditRedaction.test.js`.
- `server.js` now exports `app` and skips `listen()` under Vitest so the app can be imported in tests (production unchanged).
